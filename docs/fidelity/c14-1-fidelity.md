## 5. 見出しレベル (C16-1で追加した観点)

QAバッチ3は「5本の対比表に見出しレベルの行が1つも無い」と指摘した。Figmaには
hタグ相当の情報が無いため、**Figma側は「フレームの入れ子」を、実装側は実DOMの
アウトライン実測**を突き合わせる。

| 画面 | Figmaのフレーム構造 | C16-1前 (実測アウトライン) | C16-1後 (実測アウトライン) | 判定 |
|---|---|---|---|---|
| elxea Journal一覧 | `Content` 直下に `HeroFeature` と `Main (グリッド+サイドバー)` が**兄弟** (`8085:4299`) = カード帯を束ねる節が無い | `h1(44) → h2(24 今月号) → h2(14)x5` | **同じ (変更なし)** | [OK] 兄弟なのでカード同士が同レベルで正 |
| 著者ページ | 記事帯は節見出し「この人の記事」を**持つ** (テンプレ `7822:37213` の節) | `h1(44) → h2(20 節) → h2(14)x7` | **`h1(44) → h2(20 節) → h3(14)x7`** | [OK] C16-1で是正 |
| レベルの飛び (両画面) | — | 0件 | 0件 | [OK] |
| タグと視覚サイズの逆転 (両画面) | — | 0件 | 0件 | [OK] |

**著者ページを是正した理由**: 節見出し「この人の記事」とその子カードが同じ`h2`だと
文書アウトラインが平坦になり、スクリーンリーダの見出しジャンプで節境界が失われる。
`ArticleCard` に `headingLevel` prop (既定 `h2`) を足し、この帯だけ `h3` を渡した。
**体裁は1pxも変わらない** (`globals.css` の `article-card-title` 規則がh2 / h3の
どちらにも同じ `body-sm` を当てる)。PC / SPのフルページスクショは
**バイト単位で同一** (下記ゲート結果)。

**elxea Journal一覧を変えなかった理由**: 導出元 `8085:4299` を再取得したところ、
`HeroFeature (今月号)` と `Main (グリッド + サイドバー)` は `Content` 直下の
**兄弟フレーム**で、グリッドを束ねる節フレームが無い。つまり今月号のカードと
グリッドのカードは**同階層の別ブロック**であり、どちらも `h1` の直下 = `h2` が正。
ここでグリッドだけ `h3` にすると「グリッドの記事は今月号の記事の子」という
誤った入れ子を作るため、変更しなかった (確認事項に記載)。

## 注記

- **注1 — 行高・字間はトークンが正**。`typography.style.*` トークンのlh / lsはFigmaの
  Inter / Noto Sans JP実測lhとトークン丸めで2〜10pxずれる (例caption lh18 → 21、
  overline ls1.5 → 1.8、実数値lh35 → 44.8)。**生pxを書かない規律**のためトークンを正とした。
  R2実装10画面すべてで共通の既知差で、本レーンで新たに生じたものではない。
- **注2 — 主見出しは44pxの裁定に従う**。「ページ主見出しは一覧・詳細とも **PC 44 / SP 32**」
  の裁定 (2026-08-08) により `.page-title` (displayトークン44px / md+ のみ) を当てた。
  Figmaの52 (一覧) / 32 (People詳細) の束縛はこの裁定で置き換わっている。
  **SPはどちらも32でFigmaと一致**。`journal-list.tsx` の `StackPageHead` と同じ扱い。
- **注3 — 今月号の見出しは共有部品の既知差**。`hero-feature-title` は素の `h2` で、
  `globals.css` のunlayeredな `h2 { font: … }` (h2トークン24px) が当たる。
  **C4-3 (プレイリスト一覧) が同じ差を `[OK] 注3` として記録済み**。ジャーナル一覧・
  プレイリスト一覧と同一部品なので本レーンでは触っていない (直すと3画面が同時に動く)。
- **注4 — カード写真の263pxはFigmaのオーサリング副作用**。Figmaの
  `ArticleCard / ImageCard` は**名前で `aspect 3/2` を宣言**しているが、instanceの高さは
  **PC 452幅でもSP 164幅でも同じ263px** で固定されている。同一の263が異なる2つの
  幅に付くのはアスペクト比ではありえないため、263はinstance固定高と判断し
  **宣言値の3/2を正**とした。実装は452x301.3 / 163.5x109。
  ジャーナル一覧・プレイリスト一覧も同じ扱い (共有 `ArticleCard`)。
- **注5 — MoreRowは「残り件数 > 0」のときだけ出る**。計測時のデータは見本6件で、
  1件が今月号に上がるため残り5件 < 初期表示6件 → **枠ごと出さない**
  (空枠を出さない方針)。部品自体はジャーナル一覧・プレイリスト一覧で実測済み。
- **注6 — 記事の札列は「PC = テンプレ / SP = 記事グリッド」の合成**。People詳細テンプレの
  札列はPC 3列416 (Figma `7822:37492` / `37496` / `37500` = x64 / 512 / 960)、SPは縦積み。
  ただしテンプレの札は**人物カード** (写真 + 氏名 + 肩書) で、本節に並ぶのは**記事カード**。
  そこでPCはテンプレの3列416に厳密に合わせ、SPはR2共通リストパターンの
  記事グリッド (2列163.5) に合わせた。両方を満たす共有 `CatalogGrid`
  (`grid-cols-2 … lg:grid-cols-3 lg:gap-x-8`) をそのまま使い、新規部品は起こしていない。

## 確認事項 (Setaka判断)

1. **この2画面はR2確定版が無い状態のまま進めてよいか**。一覧はR1が【廃止】、
   著者は【廃止: People詳細へ統合】で、どちらも専用の確定版フレームが存在しない。
   本実装は凍結済み兄弟から導出した。**designerにR2を起こしてもらうか、
   この導出を確定版として扱うか**の判断 (C9-1と同じ論点)。
2. **著者ページのルートを2本残したままにしてよいか**。凍結決定は「著者 → People詳細へ統合」
   なので、本来は `/journal/author/[slug]` を `/people/[slug]` に寄せて1本にするのが筋。
   ただしPeople詳細は**別レーンの担当**で、転送を入れると相手のレーンに踏み込む。
   今回は**両ルート併存のまま、著者側をテンプレ準拠に揃える**にとどめた。
   統合するなら別タスクが必要。
3. **一覧からテーマの色 (茜 / 翠 / そひ の色バッジ) が消えたことの是非**。R2共通リストパターンの
   「ピル型統一」に従い色オーバーレイを外し、テーマは文字のキッカーにした。
   ブランドの色を一覧に戻したいならFigma側に枠を足して凍結が必要 (コードで先に生やさない)。
4. **elxea Journalに発行日・号番号のフィールドが無い**。`journal` スキーマは
   `title` / `theme` / `summary` / `featured` などを持つが**日付を持たない**ため、
   並び替え (新着順 / 古い順) はSanityの `_createdAt` を根拠にした。
   「第N号 / 2026.08」のような号表記を出すなら `issueNumber` / `publishedAt` の追加が要る
   (カードのメタ行も現状は空で出ない)。
5. **著者の実データが薄い**。author 5件のうち `role` / `bio` / `website` / `image` を
   持つものが**1件も無い** (`roji 編集部` と `Setaka` がrole + bioのみ)。
   計測は `PREVIEW_SEED=1` の見本で埋めて行った (フラグ未設定時はbyte-identical)。
   実データ投入は事業側の作業。
6. **(C16-1追加) elxea Journal一覧のカード見出しをh2のまま据え置いた**。Bossの裁定文は
   「elxea Journal一覧のカード見出しもh3」だったが、導出元 `8085:4299` で
   `HeroFeature (今月号)` と `Main (グリッド + サイドバー)` が**兄弟フレーム**であり
   グリッドを束ねる節フレームが無いため、グリッドだけh3にすると「グリッドの記事は
   今月号の記事の子」という誤った入れ子になる。加えて今月号は編集判断で出ない場合があり
   (`featured` が無いとき)、そのときh1→h3のレベル飛びになる。**現状 (h2) でよいかの確認**。
   同じ `JournalGrid` を使う `/ja/journal` `/ja/playlists` `/ja/journal/category/[slug]`
   `/ja/journal/tag/[slug]` は節見出しを持たないので、共通部品を一律h3にする案は採れない。
7. **(C16-1追加) SPの記事グリッド行間32は据え置いた** (QAバッチ3 WARN2)。導出元
   `8085:4376` が明示的に32だったため。`JournalGrid` (32) と `CatalogGrid` (24) は
   別テンプレ由来なので値が違うのが正、という整理でよいかの確認。
