## B-7. PortableText最終ブロックの下マージン漏れ — 全画面の横断実測 (C9-1R)

**結論 (事実)**: 漏れは**お茶メニュー詳細だけの問題ではなかった**。同じ経路を持つ
**農家詳細でも実測16pxの漏れ**があり、ページごとに貼るのをやめて**共有シリアライザ1箇所**
(`components/sanity/portable-text.tsx` の各ブロックに `last:mb-0`) で閉じた。

**修正方法の判断**: ラッパ要素は足していない。記事詳細 (`prose-custom` 枠) と
elxea Journal詳細 (`ArticleProse`) は `[&>*]:mb-0!` / `[&>*+*]:mt-6!` という**直下子
セレクタ**で縦リズムを組んでいるため、`div` を1枚挟むと (`display: contents` でも)
それらが全滅して段落間24が消える。よってDOM構造を変えずクラスだけで閉じた。
`app/globals.css` は同時進行のDSレーンが触っているため使っていない。

計測は**修正前ビルドと修正後ビルドの2サーバを同一ハーネスでA/B**。
「最終ブロックmb」= 本文枠の最終要素の `getComputedStyle().marginBottom`。
「節間」= 本文枠の下端 → 次節の中身の先頭 (`getBoundingClientRect`)。

| 画面 | 本文の実データ形式 | 最終ブロックmb (前 → 後) | 節間の実測 (前 → 後) | ページ全高 (前 → 後) | 判定 |
|---|---|---|---|---|---|
| お茶メニュー詳細 (実データ) `/ja/tea-menu/spring-sencha` | PortableText 1ブロック | **16 → 0** | **SP 80 → 64** / PC 128 → 128 | SP 2388 → **2372** (-16) | [OK] |
| お茶メニュー詳細 (見本データ) `/ja/tea-menu/seed-tea-1` | 素の文字列 (PTを通らない) | 該当なし | SP 64 → 64 (不変) | 2623 → 2623 (0) | [OK] |
| 農家詳細 `/ja/farmers/[slug]` (bio) | PortableText 3ブロック | **16 → 0** | **PC/SP 64 → 48** | SP 9307 → **9291** (-16) | [OK] 注11d |
| 記事詳細 `/ja/journal/[slug]` | PortableText 28ブロック | 0 → 0 (元から漏れなし) | 不変 | 6293 → 6293 (0) | [OK] |
| elxea Journal詳細 `/ja/elxea-journal/[slug]` | PortableText 11ブロック | 0 → 0 (元から漏れなし) | 不変 | 3959 → 3959 (0) | [OK] |
| イベント詳細 `/ja/events/[slug]` | PortableText 4ブロック | 0 → 0 | 不変 | 2581 → 2581 (0) | [OK] 注11e |
| プレイリスト詳細 `/ja/playlists/[slug]` | 実データに `body` が**0件** | 計測不能 | 計測不能 | 計測不能 | [SKIP] 注11f |

注11d: **農家詳細は64 → 48になった。これは是正であって回帰ではない**。`FarmerSection` の
下余白は `pb-12` = **48**で、C4-4a忠実度表も「節の下余白を48に統一【仕様】注7」と
**48を記録している**。ところがbio (紹介文) 節だけはPortableTextを含むため漏れ16が乗って

bio節が他のFarmerSectionと同じ48に揃い、C4-4aの記録どおりになった。

注11e: イベント詳細は**ページ側に同等パッチ** (`[&>*:last-child]:mb-0`) が既に貼られており
元から漏れ0だった。共通側で閉じたのでページ側の指定は削除した。**前後で値が完全に同一**

### C9-1R (QA指摘修正) で新たに上がった確認事項

4. **Sanityの内容量データがschemaと食い違っている**。`teaMenu.netWeight` はschema上
   `type: "number"` (「内容量（g）」= 単位はスキーマ側が持つ前提) だが、**実データ3件は
   すべて文字列で単位入り** (`"50g"` / `"30g"` / `"60g"`)。投入スクリプト
   `scripts/seed-dummy-content.ts` も `netWeight: "50g"` と文字列を書いている。
   表示側は正規化 (`lib/format-net-weight.ts`) で両方を吸収したので**画面は正しい**が、
   データ側をどうするかは判断が必要:
   - (a) 表示側の正規化だけで運用を続ける (今回の実装。データ移行なし・Studioで
     文字列を入れても壊れない)
   - (b) データを数値に寄せる (schemaどおり。Studioの必須バリデーションと整合するが
     既存3件のマイグレーションと投入スクリプトの修正が必要)
   **推奨は (a) を維持しつつ投入スクリプトだけ数値に直す**。正規化は残すべき
   (Studioで手入力される限り文字列は再発しうる)。今回は投入スクリプトを**触っていない**
   (実データを書き換える副作用を避けたため)。
5. **プレイリスト詳細の本文 (`body`) が実データに1件も無い** (playlist 2件はいずれも
   `description` のみ)。画面側にはPortableTextで描く枠があるが**実質デッドパス**で、
   今回も実測できなかった (注11f)。枠を残すか、`description` に寄せて枠を落とすか。
6. **農家詳細の紹介文節が64 → 48に変わった**。C4-4a忠実度表が記録している48に
   揃った是正 (注11d) だが、**見た目が変わる画面が本レーンの2画面の外に1つある**
   ことの共有。意図どおりでよいかの確認。
