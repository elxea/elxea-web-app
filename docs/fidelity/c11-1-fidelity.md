  突き合わせる (内容カラムFigma 343 → 実測358、外余白16は同値)。
- console error / warning / pageerror **0件** (requestfailed 78はRSC prefetch中断と
  Sentryのみ。詳細は `/tmp/c11-measure.json` の `console`)。
- **rebase後の再計測で差分0件**。並行レーン (C10-1 / C14-1 / C15-1 ほか) のコミットを
  取り込んだ上で同一ハーネスを再実行し、1670キーを機械比較して全一致を確認した
  (`/tmp/c11-measure.json` vs `/tmp/c11-measure-after.json`)。console error / warning /
  pageerror も再計測で0件。
- 判定の凡例:

  - `[仕様]` 意図的にプロジェクト裁定・DSトークン・共有部品の骨格へ寄せた差分
  - `[DS案件]` DS全域のトークンドリフト。**本レーンでは直さない**
  - `[粗]` 未解決の実装粗
  - `[SKIP]` 実データが無く計測できない項目 (推測値は載せない)

## 累積差分について (ページ総高)

| 項目 | Figma | 実装 | 差 |
|---|---|---|---|
| PC本文の終端 (フッター直前) | 5188 | 5296 | +108 |
| SP本文の終端 (フッター直前) | 5341 | 5551 | +210 |

差分の**主因**は行高 (line-height) のCJK再束縛と、Statement / 01の本文を2段落に
分けたことである。ただし**「すべて」ではない**。列幅・x座標はほぼ完全一致だが、
**節の下余白には行高由来でない差が含まれる**。C16-1 (QAバッチ3の指摘) で
1節を分解実測して確定した内訳は次のとおり。

### 分解実測 — 06会社情報 (SP 375 / 導出元 `8121:1386` h512)

実装実測557.94 / Figma 512 → **+45.94**。内訳は3つに分かれる (合計が一致する)。

| 内訳 | 実装実測 | Figma実測 (ノード) | 差 | 由来 |
|---|---|---|---|---|
| ヘッダ帯 (節上端 → 定義リスト上端) | 150 | 144 (`8121:1387` y48 → 罫線 `8121:1389` y144) | **+6** | 行高。キッカーh21 vs 17 (overlineのCJK再束縛) + 節見出しh29 vs 27 |
| 定義リスト (上端 → 最終値の行ボックス下端) | 367.94 | 351 (y144 → `8121:1403` y470 + h25 = 495) | **+16.94** | 行高。行ピッチ75.19 vs 72 (x4行) |
| **下余白 (最終値の行ボックス下端 → 節下端)** | **40** | **17** (512 − 495) | **+23** | **行高由来ではない**。`MetaRow` の行下padding 8 + 節の `pb-8` (32) が、Figmaの17 (spacing scaleに無い値) を8の倍数に丸めた結果 |
| 合計 | 557.94 | 512 | +45.94 | — |

**事実**: 下余白の +23はline-heightではなくspacing scaleへの丸めから来ている。
**判断**: これは「生pxを書かずspacing scaleだけを使う」という本プロジェクトの制約の
帰結であり、Figmaの17を再現するには生px (`pb-[17px]`) が必要になる。丸めを外す
判断はDS側の案件なので本レーンでは変えない。**PC総高 +108 / SP総高 +210のうち、
同種の下余白の丸めが各節に効いている分は行高差とは別枠**として読むこと。

行高の再束縛は `dist/tokens-cjk.css` が `:lang(ja)` で `--typography-style-*` の
lineHeightを上書きするもので、**全R2ページ共通の既知差分**。FigmaとCJK
オーバーライドのどちらを正とするかは未決 (All Tasks「Review: CJK文字組みトークン
vs Figmaの食い違いの正を決める (roji)」`3b570c9d-064c-81b7`)。本レーンでは触らない。
